LessonPlanToGo: production Blue Team assessment

Completed 6 October 2026. Public, unauthenticated configuration assessment through Command Deck MCP and bounded HTTP/TLS verification.

Command Deck baseline: A / 100 out of 100. No critical, high, medium, or low scanner findings; one informational server-banner finding. Manual review identified a CSP hardening opportunity and coverage limitations. This score describes this scanner's checks, not comprehensive application security.

Scope and method

The authorized production target was lessonplantogo.onrender.com. It redirected to lessonplantogo.church-care-hub.workers.dev. The root-page header and CORS requests followed that redirect; TLS was verified independently for both hosts. Ten sensitive file paths and a nonexistent control path were requested individually at both origins. No credentials, customer records, exploitation, or state-changing application requests were used.

Command Deck run: 2026-10-06 18:26:40 UTC. Supplementary evidence collected at 2026-10-06T18:28:13.486080+00:00. Evidence retains status codes, byte counts, hashes and public configuration; cookie values and response bodies are excluded.

Findings and recommendations

  1. Informational — server banner. Server: cloudflare identifies the edge provider. No version disclosure or exploit was demonstrated. Accept this as provider metadata or suppress it if the platform permits and policy requires.
  2. Low-priority hardening observation — inline CSP allowances. The observed CSP includes 'unsafe-inline' in script-src and style-src. For script-src, this weakens inline-script protection; no injection vulnerability was demonstrated. Consider tested nonces or hashes, reduce broad third-party source allowances, and validate authentication, challenge and font integrations before rollout.
